# 📘 AWS Databases – Overview Notes

## 1. Introduction

Databases are a **core component of any application** and a **key topic for AWS exams**.  
AWS provides a wide variety of database services, each designed for **specific use cases**.

👉 Instead of relying on a single database type, modern systems use **purpose-built databases** optimized for different needs.



## 2. Why So Many Database Types?

### Evolution of Applications

Applications have evolved significantly over time:

- **Mainframe systems (1930s–40s)**
    
- **Client-server architecture**
    
- **Three-tier architecture**
    
- **Modern microservices architecture**
    

### Key Insight

In modern architectures:

- Each microservice may have its **own database**
    
- Different services require **different data models**
    

➡️ Result: One database type is no longer sufficient → **Need for multiple specialized databases**

# 📘 AWS Shared Responsibility Model for Databases (Simplified Guide)

## 1. ❓ Why Do We Need Managed AWS Database Services?

Before diving into AWS database services, let’s address an important question:

👉 **Why not just run databases on EC2?**

Yes, you _can_ install databases on EC2, but then **you are responsible for everything**, including:

- Managing EC2 instances
    
- Ensuring high availability
    
- Taking backups
    
- Performing patching and upgrades
    
- Handling failover and scaling
    
- Monitoring and maintenance
    

⚠️ This creates **significant operational overhead**.

---

## 2. 💡 What is the AWS Shared Responsibility Model?

AWS operates on a **shared responsibility model**:

> **AWS = Security _of_ the Cloud**  
> **You (Customer) = Security _in_ the Cloud**

### What does this mean?

|Responsibility Type|Who Handles It|
|---|---|
|Physical data centers|AWS|
|Hardware & networking|AWS|
|Hypervisor|AWS|
|OS configuration|Customer|
|Application & data|Customer|

---

## 3. 🖥️ When You Use EC2 for Databases

If you host your database on EC2:

### 🔧 AWS Handles:

- Physical infrastructure
    
- Hardware
    
- Networking
    
- Hypervisor
    

### 👨‍💻 You Handle:

- OS installation & patching
    
- Database installation
    
- Backups & restores
    
- High availability setup
    
- Scaling & replication
    
- Monitoring & maintenance
    

👉 **Conclusion:** You have full control, but also full responsibility.

---

## 4. 🗄️ When You Use Managed AWS Database Services (RDS, DynamoDB, etc.)

Managed services shift most responsibilities to AWS.

### 🔧 AWS Handles:

- Database provisioning
    
- Underlying infrastructure
    
- Automated backups
    
- OS patching
    
- Database patching
    
- High availability (Multi-AZ)
    
- Maintenance & updates
    

### 👨‍💻 You Handle:

- Database schema design
    
- Query optimization
    
- Access control (IAM, security groups)
    
- Deciding public vs private access
    
- Data management
    

👉 **Conclusion:** You focus on **business logic and data**, not infrastructure.

---

## 5. ⚖️ EC2 vs Managed Databases (Quick Comparison)

|Feature|EC2 Database|Managed DB (RDS, etc.)|
|---|---|---|
|Setup complexity|High|Low|
|Maintenance effort|High|Low|
|Control|Full|Limited|
|Automation|Manual|Built-in|
|Cost|Lower|Slightly higher|
|Scalability|Manual|Easier|

---

## 6. 💰 Cost vs Value Trade-off

- EC2 databases → cheaper upfront
    
- Managed databases → higher cost but:
    

✔️ Less operational effort  
✔️ Built-in reliability  
✔️ Faster development  
✔️ Reduced risk

👉 In most real-world scenarios, **managed services are worth the cost**.

---

## 7. 🧠 Final Summary (Exam / Interview Ready)

👉 **AWS manages:**

- Infrastructure
    
- OS & DB patching
    
- Backups
    
- High availability
    
- Maintenance
    

👉 **You manage:**

- Data
    
- Schema design
    
- Access & security configuration
    
- Network exposure (public/private)
    

---

## 8. 🎯 Key Takeaway

> **Use EC2 if you want full control.**  
> **Use managed databases if you want simplicity, scalability, and reliability.**
