**Streaming data = continuous, real-time flow of data**

- Website clicks

```text
Batch → stored first → processed later  
Streaming → processed as it arrives
```

# ⚡ 3. Lambda Processes the Stream

## 💡 What’s happening?

Lambda is triggered automatically when new records arrive.

---

## 🔄 Flow:

1. Kinesis batches records
    
2. Lambda receives batch
    
3. Processes events
    

---

## 🛠️ Example Lambda (Python)

```python
import json

def lambda_handler(event, context):
    processed = []
    
    for record in event['Records']:
        payload = json.loads(record['kinesis']['data'])
        
        # Filter bots
        if payload.get("user_id") == "bot":
            continue
        
        # Count clicks
        processed.append({
            "user_id": payload["user_id"],
            "action": payload["action"]
        })
    
    return processed
```

---

## 🎯 What you can do here:

### ✔️ Filtering

- Normalize schema
    

### ✔️ Aggregation

- Count clicks per user
    
- Session tracking
    

---

## ⚠️ Important

- Lambda processes **batches**, not single events
    
- Scaling = **per shard**
    

👉 More shards → more parallel Lambdas

# 🧠 1. What is Amazon Data Firehose?

**Amazon Kinesis Data Firehose = fully managed data delivery service**

## 💡 Simple idea:

```text
Source → Firehose → Destination
```

# 🔄 2. Where Firehose Fits

```text
Producers / Kinesis / MSK → Firehose → S3 / Redshift / OpenSearch / HTTP
```

---

## 🔌 Supported Sources:

- Amazon MSK (Kafka) ✔️
- Direct PUT (SDK / Agent) ✔️

## 🎯 Destinations:

- Amazon S3
- Amazon Redshift
- Amazon OpenSearch
- HTTP endpoints
- Third-party (Splunk, Datadog)

# ⚡ 3. What Firehose Actually Does

Firehose is NOT a processor like Flink ❗

👉 It mainly handles:

## ✔️ 1. Buffering (Batching)

- Collects records
- Sends in batches
### Config:

- Buffer size (e.g., 5 MB)
- Buffer interval (e.g., 60 sec)


## ✔️ 2. Delivery

- Automatically pushes data to destination
- Retries on failure


## ✔️ 3. Transformation (Optional)

Using **Lambda**

```text
Incoming data → Lambda → Transformed → Destination
```

## ✔️ 4. Format Conversion (Built-in)

- JSON → Parquet / ORC
- No Lambda needed

🔥 Very important for analytics


## ✔️ 5. Compression

- GZIP
- Snappy

👉 Reduces storage cost


## ✔️ 6. Backup to S3

- Store all raw data
- Store failed records


# 🧱 4. Internal Flow (Clean)

```text
Source → Firehose Buffer → (Optional Lambda) → Format Conversion → Compression → Destination
```


# ⚠️ 5. Important Clarifications

## ❗ A. Firehose ≠ Kinesis Data Streams

|Feature|Kinesis Data Streams|Firehose|

|Processing|Custom|Limited|
